# ChatBot 2.6.0 验证记录

本轮用用户提出的“启动可用、统一命名、前后端优化”作为验收目标。全部模型验证使用本机 HTTP 模拟服务，未访问收费模型、未向微信联系人发送消息。

## RED → GREEN

| 用户可观察的保证 | 初次复现 | 修复验证 |
|---|---|---|
| 突发更新只发送最新状态 | 100 次变更产生 100 份快照 | 合并为 1 份，内容为最后状态 |
| 关闭后不再推送状态 | 关闭前排队更新已立即发出 | 关闭后队列丢弃 |
| 错误请求不能进入控制器 | 5 种错误数据中 3 种到达 handle | 全部拒绝并返回结构化错误 |
| 模型进程启动失败不遗留管道 | 两个管道端点均未关闭 | 两端及进程对象清理通过 |
| 同一数据目录只启动一份 | 单实例模块尚不存在 | 第二实例发出激活通知，退出后可重新取得锁 |
| 产品与构建名称统一 | 当前规格文件不存在，代码有混合名称 | 品牌与包装测试通过 |
| 长聊天按需渲染 | 1000 条记录首次建立 1000 个消息节点 | 首次 200，展开后 400，定位旧消息可自动展开 |
| 状态变化不打断阅读和输入 | 气泡重建，改写输入焦点丢失 | 消息节点身份、输入内容及光标范围保持 |

## 执行命令

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe scripts/smoke_chatbot.py --output work/chatbot-ui
.\.venv\Scripts\python.exe scripts/check_secrets.py --tree .
```

原生界面验证直接使用应用自身 QtWebEngine 与真实 QtWebChannel，以合成数据经过实际控制器走完：加载 → 状态变更 → 追加消息 → 展开历史 → 定位旧消息 → 设置抽屉 → Escape → 小窗。检查标题、非空工作台、JavaScript 错误、焦点、滚动和 1280×850 / 520×780 布局，并人工查看截图。

正式构建已运行全部 474 项：472 项通过，2 项平台条件跳过。原生 UI 的 13 项检查通过。打包程序另通过 14 项离线自检。

覆盖率工具单独放在任务工作区，不加入应用依赖。三个本轮涉及的运行模块合计约 80%：bridge 100%，新增 instance 91%，tasks 69%；后者的子进程模型分支并未被完整计入父进程覆盖率。控制器及整个历史项目不声明达到此覆盖率。

源码扫描无发现。本机数据在安装替换前后独立核验；打包程序的离线自检和快捷方式启动结果保存在任务验收记录。源代码没有 Git 仓库，未创建虚假提交；原始源码与 RED/GREEN 日志保留在任务工作区。

## 未验证范围

收费模型真实推理、真实联系人自动发送、macOS 原生构建、Windows 重启后自动恢复未在本轮验证；自动回复的现有保护逻辑保留。字体与依赖的锁定版本沿用，不以无依据的大规模升级代替兼容性验证。
